# Saad Murtaza Khan — Quarto portfolio and blog

The website is now built with Quarto. It retains the white background, the original illustrated Anatomy of a Method header, navigation below the figure, and separate Research, Publications, Software, Blog, Contact, and About pages. The CV download and removed Research introductory sentence are absent.

## What is delivered

The ZIP contains two folders:

- `quarto-source/`: editable Quarto project. Keep this in your PRIVATE `smk5g5/website` repository.
- `public-site/`: generated website. Upload its CONTENTS to your PUBLIC `smk5g5/smk5g5.github.io` repository.

The two folders are intentionally separate. Do not upload the entire ZIP or private source files to the public repository.

## Preview and render

Install Quarto from https://quarto.org/docs/get-started/ . Tested with Quarto 1.10.19.

From `quarto-source/`:

```sh
quarto preview
```

To create publishable files:

```sh
quarto render
python3 scripts/check-public-output.py _site
```

The generated files are in `_site/`. No R/Python packages or Node packages are needed for this example; its Python code is displayed rather than executed.

All pages are generated by Quarto. `publications-data.json` retains reference data; it is not fetched by the website. Update both this JSON and `publications.qmd` when changing publication entries.

## Write another post

1. Create `posts/my-next-post/`.
2. Copy `_examples/new-post.qmd` to `posts/my-next-post/index.qmd`.
3. Edit the title, description, date, categories, and body.
4. Add images alongside the post and link them relatively, e.g. `![Description](figure.png)`.
5. Preview locally. The blog index updates automatically.
6. When approved, set `draft: false`, render the public output, and publish.

The standard metadata is:

```yaml
---
title: "My next post"
description: "A short summary."
date: 2026-10-28
categories: [Bioinformatics, Methods]
draft: true
---
```

## Private drafts

`draft: true` suppresses the post in an ordinary render, but does not protect its source in a public repository. Keep source private. `quarto preview` shows drafts locally. For a hosted review build, run `quarto render --profile preview --output-dir _preview` and send ONLY that output to an access-protected preview deployment. The preview profile itself does not provide authentication.

The supplied draft template is under `_examples/`, which is excluded from the render list. A temporary test confirmed draft body text is absent from the public HTML, blog index, RSS, and search output. Do not put sensitive files into the globally copied `assets/` directory; use separate private draft assets and inspect public output before sharing.
